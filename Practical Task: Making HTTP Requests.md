# 🛠️ Task 10: Practical Task: Making HTTP Requests | مهمة عملية: إجراء طلبات HTTP

## 🇬🇧 English Documentation

### 📌 Overview

Understanding HTTP theory becomes truly effective when applied practically. In real-world web development, troubleshooting, and penetration testing, professionals rarely rely solely on standard browser navigation—they use command-line utilities, browser developer tools, and intercepting proxies to craft, modify, and inspect raw **HTTP Requests** and **HTTP Responses** manually.

### 🧰 Essential Tools for Crafting & Inspecting HTTP Requests

| Tool | Type | Primary Use Case |
| :--- | :--- | :--- |
| **`cURL`** | Command-Line Utility | Quickly sending customized HTTP requests (`GET`, `POST`, `PUT`, `DELETE`), setting custom headers, and inspecting raw server responses directly from the terminal. |
| **Browser DevTools (`Network` Tab)** | Built-in Browser Inspector | Monitoring live HTTP traffic generated by a webpage, viewing request/response headers, status codes, timing, and replaying requests. |
| **Intercepting Proxies (e.g., Burp Suite, OWASP ZAP)** | Web Security Proxy | Intercepting, pausing, modifying, and replaying HTTP/HTTPS traffic between the browser and the web server to test how applications handle manipulated inputs. |

### 💻 Practical `cURL` Examples

#### 1. Basic `GET` Request
Retrieves the content of a target endpoint:
```bash
curl http://example.com/api/items
```

#### 2. Inspecting Response Headers Only (`HEAD` / `-I`)
Fetches only the status line and response headers without downloading the body:
```bash
curl -I http://example.com
```

#### 3. Verbose Inspection (`-v`)
Displays the full request sent by the client (`>`) alongside the full response headers and body returned by the server (`<`):
```bash
curl -v http://example.com/login
```

#### 4. Sending Form Data via `POST` (`-X POST -d`)
Submits URL-encoded form parameters in the request body:
```bash
curl -X POST http://example.com/login \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "username=admin&password=password123"
```

#### 5. Sending JSON Payloads with Custom Headers
Sends structured JSON data along with an `Authorization` token:
```bash
curl -X POST http://example.com/api/profile \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1Ni..." \
  -d '{"role": "analyst", "active": true}'
```

#### 6. Updating or Deleting Resources (`PUT` & `DELETE`)
Explicitly specifies alternative HTTP methods using the `-X` flag:
```bash
# Update a resource
curl -X PUT http://example.com/api/items/5 -H "Content-Type: application/json" -d '{"name": "UpdatedItem"}'

# Delete a resource
curl -X DELETE http://example.com/api/items/5
```

### 🔍 Practical Analysis Workflow

When testing or interacting with a web endpoint manually, follow this structured workflow:

1. **Identify the Target & Method:** Determine the exact URL path (`Path`), required query parameters (`Query String`), and appropriate HTTP method (`GET`, `POST`, etc.).
2. **Set Required Headers:** Include necessary metadata such as `Content-Type`, `Cookie`, or `Authorization`.
3. **Construct the Body:** Format the payload properly (Form-encoded, JSON, etc.) and ensure the empty line separator is respected in raw requests.
4. **Analyze the Response:**
   * Check the **Status Code** (`200 OK`, `302 Found`, `401 Unauthorized`, `403 Forbidden`, `500 Internal Server Error`).
   * Inspect **Response Headers** for `Set-Cookie`, `Location`, or missing **Security Headers**.
   * Examine the **Response Body** for expected output, API data, or unexpected error messages.

## 🇸🇦 التوثيق باللغة العربية

### 📌 نظرة عامة

يُصبح فهم أساسيات بروتوكول HTTP ذا قيمة حقيقية عند تطبيقه عملياً. في بيئات تطوير الويب، وتشخيص الأعطال، واختبار الاختراق، لا يكتفي المختصون بالتصفح التقليدي عبر المتصفح فحسب، بل يستخدمون أدوات سطر الأوامر، وأدوات المطور في المتصفح، والوكلاء الاعتراضيين (Proxies) لإنشاء وتعديل وفحص **طلبات واستجابات HTTP** الخام بشكل يدوي ودقيق.

### 🧰 أبرز الأدوات لإنشاء وفحص طلبات HTTP

| الأداة | النوع | الاستخدام الرئيسي |
| :--- | :--- | :--- |
| **`cURL`** | أداة سطر أوامر (CLI) | إرسال طلبات HTTP مخصصة بسرعة (`GET`, `POST`, `PUT`, `DELETE`)، وتحديد رؤوس مخصصة، وفحص استجابات الخادم الخام مباشرة من الطرفية (Terminal). |
| **أدوات المطور (`Network` Tab)** | أداة مدمجة في المتصفح | مراقبة حركة مرور HTTP الحية التي تُنشئها صفحة الويب، وعرض رؤوس الطلب والاستجابة، ورموز الحالة، وإعادة إرسال الطلبات. |
| **الوكلاء الاعتراضيون (مثل Burp Suite وOWASP ZAP)** | وكيل أمان الويب (Proxy) | اعتراض حركة مرور HTTP/HTTPS بين المتصفح والخادم، وإيقافها مؤقتاً، وتعديل معاملاتها ورؤوسها لاختبار كيفية تعامل التطبيق مع المدخلات المتلاعب بها. |

### 💻 أمثلة عملية باستخدام أداة `cURL`

#### 1. إرسال طلب `GET` أساسي
لجلب المحتوى أو البيانات من مسار محدد على الخادم:
```bash
curl http://example.com/api/items
```

#### 2. فحص رؤوس الاستجابة فقط (`HEAD` / `-I`)
لجلب سطر الحالة ورؤوس الاستجابة فقط دون تحميل جسم الصفحة:
```bash
curl -I http://example.com
```

#### 3. العرض التفصيلي للاتصال (`-v`)
يعرض تفاصيل الطلب الكامل المرسل من العميل (`>`) جنباً إلى جنب مع استجابة الخادم الكاملة (`<`):
```bash
curl -v http://example.com/login
```

#### 4. إرسال بيانات نموذج عبر `POST` (`-X POST -d`)
لإرسال بيانات تسجيل دخول أو نموذج بصيغة URL-encoded داخل جسم الطلب:
```bash
curl -X POST http://example.com/login \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "username=admin&password=password123"
```

#### 5. إرسال بيانات JSON مع رؤوس مخصصة
لإرسال بيانات منظمة بصيغة JSON مرفقة برمز مصادقة (`Authorization`):
```bash
curl -X POST http://example.com/api/profile \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1Ni..." \
  -d '{"role": "analyst", "active": true}'
```

#### 6. تحديث أو حذف الموارد (`PUT` و`DELETE`)
لتحديد أساليب HTTP مختلفة صراحةً باستخدام الخيار `-X`:
```bash
# تحديث مورد موجود
curl -X PUT http://example.com/api/items/5 -H "Content-Type: application/json" -d '{"name": "UpdatedItem"}'

# حذف مورد محدد
curl -X DELETE http://example.com/api/items/5
```

### 🔍 منهجية التحليل العملي للطلبات

عند فحص أو التفاعل مع أي نقطة نهاية (Endpoint) يدوياً، يُنصح باتباع الخطوات المنظمة التالية:

1. **تحديد الهدف والأسلوب:** تحديد مسار الرابط الدقيق (`Path`)، ومعاملات الاستعلام المطلوبة (`Query String`)، وأسلوب HTTP المناسب (`GET` أو `POST` أو غيرهما).
2. **إعداد الرؤوس اللازمة:** إضافة البيانات الوصفية الضرورية مثل `Content-Type` أو `Cookie` أو `Authorization`.
3. **بناء جسم الطلب:** تنسيق البيانات المرسلة بالصيغة الصحيحة (نموذج أو JSON) والتأكد من وجود السطر الفارغ الفاصل في الطلبات الخام.
4. **تحليل الاستجابة المُعادة:**
   * التحقق من **رمز الحالة** (`200 OK`، `302 Found`، `401 Unauthorized`، `403 Forbidden`، `500 Internal Server Error`).
   * فحص **رؤوس الاستجابة** بحثاً عن `Set-Cookie` أو `Location` أو التحقق من وجود **رؤوس الأمان**.
   * مراجعة **جسم الاستجابة** للتأكد من النتيجة المتوقعة أو اكتشاف رسائل خطأ تكشف معلومات داخلية.
